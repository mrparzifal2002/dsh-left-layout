# dsh-left-layout

[English](README.md) | 中文

一个 DeepSeek Harness（DSH）组合包插件：把侧栏的浏览区域替换为三段式 —— **功能**、**最近任务**、
**工作区**，并且功能栏可以拖动排序。

```
┌────────────────────────────────┐
│  DSH                       ▸   │  原生外壳（保留）
├────────────────────────────────┤
│  + 新会话                       │  常驻，不可拖动
│  Docker                    ⠿   │  已提到的功能，
│  技能                      ⠿   │  可拖动排序
│  更多 (3)                       │
├────────────────────────────────┤
│  重构加载器                 ⋮   │  任务：最近 30 天
│  修拖拽排序                 ⋮   │  内的最新 5 条
│  查看更多                       │
├────────────────────────────────┤
│  ▾ dsh-plugins         +   ⋮   │  工作区，可展开
│      修拖拽排序             ⋮   │
└────────────────────────────────┘
```

## 为什么

原生侧栏是一条扁平的滚动列表：所有已注册面板都压在对话之上，无法把常用的面板留在手边。本插件
按用途把这块区域拆成三段，把最可能重新打开的 5 条对话留在顶部，并让你自己挑选、自己排列功能栏。

原生外壳保持原样：品牌行、收起轨道、底部设置入口、标题栏的新会话控件都不动，只替换浏览区域。

## 功能

### 功能栏

- **新会话** 固定在顶部，始终可见。
- 其他所有功能 —— 既有内置面板，也有「技能」这类只在设置里存在的功能 —— 都可以**提到**栏上，
  或者留在 **更多** 里。
- 已经提到外面的功能可以**任意拖动排序**，刷新后顺序保持。
- **更多** 按钮会显示当前被收起了多少个功能。
- **更多** 菜单中每一行有两个独立操作：勾选框负责在功能栏与「更多」之间移动功能；点击图标或
  名称则直接打开该功能并关闭菜单。
- 只在设置里存在的功能本身没有侧栏面板。点击 **技能** 时：技能管理器主面板存在则直接打开它，
  否则打开设置并定位到「技能」页。

### 任务区

- 列出 DSH 自动创建的默认工作区中的对话，以及没有归属任何工作区的对话。
- 最后活动时间在 30 天内的对话视为「最近」；只显示最新的 5 条，**查看更多** 会展开完整列表
  （包括更早的对话）。
- 鼠标移到行上出现三点菜单：**置顶**（已置顶时显示 **取消置顶**）、**重命名**、**打开本地文件夹**、
  **归档**、**删除任务**（红色）。归档会先停止仍在运行的工作。
- 已归档会话与 subagent 来源的会话不显示。

### 工作区

- 每个显式注册的工作区占一行；展开可查看其中的对话，点加号可登记新目录。
- 鼠标移到行上出现三点菜单与「新建对话」按钮。菜单提供 **打开本地文件夹**、**重命名**、
  **删除该工作区**（红色）。

## 安装

依赖：

| | |
|---|---|
| DSH | `>=0.2.1-rc.2 <0.3.0-0` |
| Node | `>=22.19.0`（仅从源码构建时需要） |
| React | `^18.2.0`（由宿主提供） |

从本仓库的检出版本安装：

```bash
git clone https://github.com/mrparzifal2002/dsh-left-layout.git
cd dsh-left-layout
npm install
npm run build          # 仅在你改过 src/ 之后需要，lib/ 已随仓库提供
```

把它链接进 profile，并登记为组合包：

```bash
pnpm add link:/absolute/path/to/dsh-left-layout
```

在 profile 的 `package.json` 中把 `dsh-left-layout` 加入 `dsh.profile.bundles`。组合包的
`cordis.patch.yml` 会自行插入 loader 行，无需另写 patch 条目。

重启 GUI，三段式布局即生效。

## 关闭它

「设置 → 插件」会像其他插件一样列出本组合包。在那里关闭即可立即恢复原生侧栏，重新启用即可恢复
三段式布局。插件不持有任何服务端数据，卸载时会移除自己注入的样式与 DOM 标记。

## 存储了什么

所有状态都按浏览器保存在 `localStorage`，不出本机，也不写入 profile。

| 键 | 内容 |
|---|---|
| `dsh-left-layout:promoted:v1` | 功能栏上的功能 id 有序列表。数组顺序**就是**显示顺序。 |
| `dsh-left-layout:hidden-tasks:v1` | 通过 **删除任务** 隐藏的对话 id。 |
| `dsh-left-layout:skills-seeded:v1` | 一次性标记，避免用户主动取消「技能」后又被自动加回功能栏。 |

想重置布局：删掉上述键后刷新页面。

## 行为细节

- **默认工作区**：任务区把产品自动创建的默认工作区（`.../deepseek-harness/default-workspace`，
  标题 `default-workspace`）当作任务桶；显式工作区留在下方工作区段。
- **新会话位置**：默认工作区已注册时，「新会话」在该工作区中创建；默认工作区缺失时回退到 DSH
  原生的「当前工作区 / 最近工作区」选择。
- **空白会话** 不列入任务。新会话按钮仍会创建一个，对话有内容后才会出现对应行。
- **拖放语义**：落在目标行的上半部分插到它上方，下半部分插到下方，目标行会出现提示线。新勾选的
  功能追加在末尾；取消勾选后再勾选也会回到末尾。
- **「删除任务」是本地隐藏**：DSH 不提供删除会话日志的能力，因此对话只是从这个侧栏消失，日志不动。
- **侧栏收起时** 浏览区域整体隐藏（这是原有设计），标题栏的新会话控件仍然保留，仍可开始对话。

## 开发

```bash
npm install
npm run typecheck      # tsc --noEmit
npm run build          # src/client.tsx -> lib/client.js + lib/types/
```

| 路径 | 作用 |
|---|---|
| `src/client.tsx` | 全部功能：布局组件、样式、存储、i18n 表。 |
| `src/index.ts` | 空壳宿主半侧 —— 插件完全在浏览器侧运行。 |
| `scripts/build.mjs` | 把客户端转译成 `window.__ModuleLoader__` 工厂包，并输出声明。 |
| `lib/` | 随仓库提交的构建产物，检出即可运行，无需先构建。 |
| `locale/` | 插件列表里的面板标题与描述。 |

`lib/` 会随 `src/` 在同一次提交里同步更新。构建写入前会统一行尾，因此在 Windows 与 Linux 上重新
构建得到逐字节相同的产物 —— 改一行源码只会产生一处小 diff，而不是整文件的行尾噪声。

## 已知限制

- **只支持鼠标**。功能栏拖动基于原生 HTML5 拖放，触屏与纯键盘操作均不支持。
- **工作区拖动排序未实现**。重命名、删除、打开本地文件夹可从悬停菜单操作。
- **默认工作区的判断是约定**。依据本 DSH 版本的路径与标题；部署若改变该约定，任务区会退化为
  只显示无归属会话。
- **技能桥接走的是 DOM**。定位设置分节依赖 className 片段与分节文字，宿主改动任一项都会导致
  面板能打开但没定位到具体分节，控制台会留下 `settings section not found` 警告。
- **顺序只有一个来源**。提升数组兼任显示顺序，好处是只有一份状态而非两份；代价是取消勾选后
  再勾选会回到末尾。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 侧栏看起来没变化 | 组合包未生效：检查 `dsh.profile.bundles` → 「设置 → 插件」→ 重启 GUI。 |
| 功能栏只有「新会话」 | 还没有提到外面的功能 —— 打开 **更多** 勾选即可。 |
| 拖动某一行没反应 | 只有已提到的功能可拖动（「新会话」永远不可拖），且拖动需要鼠标。 |
| 任务区只显示无归属的对话 | 默认工作区约定与本部署不一致，见「已知限制」。 |
| 点「技能」打开了设置但没跳到技能页 | 宿主改了设置区的 DOM，见「已知限制」。 |
| 顺序或隐藏任务看起来是旧的 | 删掉上文列出的 `dsh-left-layout:*` 键后刷新。 |
